## 本轮FF/Cmd13通信排查

用户上板反馈首次按#即FF/Cmd13，接线未变。FF为等待应答超时，Cmd13是校验模块通信密码，尚未进行指纹采集。对比2026-10-19归档：原串口收发/IRQ队列、57600/8N2、PA2/PA3、系统时钟和Delay代码一致，旧接收溢出修复仍保留。本次补上main显式NVIC优先级分组2，使USART2的抢占优先级1高于TIM3的2；尚不能确认该缺口就是现场超时的根因。

当前固件在指纹错误页增加只读诊断：

- B（S8）：`C13 TX016 TC1`、`RX000 E00 D000`、最先8字节的16位十六进制显示。TX/RX/D为十进制计数，E为十六进制串口错误位，TC1表示末尾发送完成，D是软件队列丢字节数。示例行不是已取得的实物数据。
- C（S12）：串口/管脚/IRQ寄存器快照。正常72MHz系统、APB1为36MHz时预期`BRR0271 S2000`、`CR1:202C I1 P0`、`PA:8B M0 G5 Q40`。S为CR2，I是USART2中断使能，P是全局中断屏蔽，PA是PA2/3模式，M是USART2重映射，G是AIRCR分组编码，Q是USART2优先级编码。
- #按原失败流程重试，0按原权限规则返回。B/C不重新初始化或发送串口命令，显示冻结的失败现场。

本次增加了寄存器只读快照、错误计数显示及真实OLED页面回归。实际根因仍需新固件重试后的B/C数据确认；不因模拟通过就宣称通信已在实物修复。

后续现场反馈：`C13 TX016 TC1 / RX000 E00 D000`，寄存器为`BRR0271 S2000 / CR1:202C I1 P0 / PA:8B M0 G5 Q40`。发送寄存器操作和当前配置符合预期，但接收IRQ没有记录任何字节。已分别核对脚本构建与Keil构建各自的HEX/链接MAP，USART2向量均正确指向各自强定义的接收函数。两种构建的地址及散列会因优化/布局不同而不同，不能跨构建拿地址作判断。

新增D（S16）通信对照：在指纹错误页按D，依次执行同一条13命令的中断接收和前台轮询接收。页面显示`I:xx Rnnn Ehh`与`P:xx Rnnn Ehh`，xx是返回码，R是十进制接收字节数，E是串口错误位。轮询期间仅关闭USART2的NVIC通道，返回时恢复原启用状态；不改变波特率、停止位、地址、口令或指纹库，不授予管理权限。D可重复，#回原失败步骤重试，0返回。

若I超时而P成功，说明在这次轮询试验中模块应答可到达UART，接收IRQ路径仍需排查；若两者均R000，说明该次两条探测都未取得UART接收字节，还需独立排查模块应答、信号到达与UART接收状态，不能仅据此断言接线有错。

后续用户反馈两种方式均为FF/R000/E00。再次逐段核对归档，SendCmd、ReceiveAck、InitSerial、VerifyPassword以及系统时钟和Delay与已通过源代码一致（新增轮询分支只在D探测时启用）。当前缺少能够确定根因的实物证据，不继续盲改通信参数；先请用户让MCU与模块一起完整断电再供电，记录灯光/触摸反应及原步骤、D探测结果。只复位MCU不能保证同时复位独立供电的指纹模块。

**用户实测更新：完整断电重启后恢复通信。** 这证明整板断电可清除本次故障，原固定通信参数可以继续工作；不能据此确定模块此前的具体内部状态，也不能将恢复归功于优先级分组调整。通信恢复不等于三步录入、角色保存及管理员菜单已上板验收，接下来继续按本文完成首次录入和重新登录。本轮未因该结果增加未经验证的启动取消指令或改写模块参数。

## 首次部署：录一枚新指纹作为初始管理员

已有测试指纹保留，不自动获得管理员权限。请选择一枚模块尚未录入的手指。

1. 主页A显示`FIRST ADMIN / New admin finger / # Begin 3 steps`；0可返回主页。
2. 按#检查通信、找空闲ID并记录待完成事务，显示`ENROLL 1/3`；尚未采集。
3. 放上新手指，按#，第一次采集并检查是否已存在，成功显示`ENROLL 2/3`。
4. 移开手指，按#，实际检查确已移开，成功显示`ENROLL 3/3`。不松手会报`Lift finger now`；错误页#回该步骤，再按#重新检查。
5. 再放回同一手指，按#，二次采集、比较合并、检查目标ID未占用、存模板、回查占用并提交管理员名单。
6. 全部成功才显示`COMPLETED / Admin FP saved`，约1.5秒后回`ADMIN VERIFY`。再用新指纹按#验证，通过后进入管理流程。

长按#不能跨步骤，须释放后重新按。各步骤0取消；已有模板/角色不删除。`Finger exists`表示这枚手指已经录过，换一枚新手指；`Different finger`表示两次不是同一手指，#重走三步。

无有效四套口令时，管理员验证成功后显示`NO PASSWORDS / # Init samples`。按#才初始化以下已同意的样例，成功后回菜单；0先回菜单，不写入。已有有效配置不覆盖。

## 四功能菜单

菜单：`1Normal 2Duress / 3 Add admin FP / 4 Audit logs / 0 Logout`。

### 1 普通密码、2 胁迫密码

按1或2→选择1数字、2旋钮→第一次输入#→第二次输入#→一致且保存回读成功，显示`Password saved`，约1.5秒回管理员菜单，新口令立即生效。

- 数字六位1～9，星号遮挡，*每次删一位、0退出；`1st #OK`/`2nd #OK`区分两遍。数字0不用于口令。
- 旋钮三段交替方向，每段1～99格，反转分段、*清空、#提交，右下角区分两遍。不足三段不提交，输入溢出须清空。
- `Inputs differ`：两次不同；`Normal=duress`：同种方式的普通/胁迫相同；`Save failed`：保存失败。错误页#回方式选择、0回菜单，原有效口令保留。
- 只修改选中的一套，其他三套保持原样；中途0取消不保存。

### 3 新管理员指纹

按3复用上述三步#确认，成功返回管理员菜单。新增指纹仅用于管理入口。名单最多16枚；名单或模块库满则报错，不覆盖已有指纹。本轮最新四项需求中没有删除功能，故不提供删除。

错误页显示原因及`Code:xx Cmd:xx`；#按提示重试，0回菜单。FA表示MCU管理员名单保存失败，FB表示尚未移开手指。

### 4 日志审查

- 4进入默认最新记录；顺时针看更旧、逆时针看更新，到两端停止。
- #只读重扫，C显示数量/待写/存储错误，0回管理员菜单。
- A/B不追加TEST、不进入批量写入，管理员查看页为只读。
- NUM/DIAL是日常数字/旋钮认证；PASS/FAIL为结果，D:1为胁迫成功。普通和胁迫对外均显示PASS。
- FING记录完成的管理员比对：名单内PASS、未匹配或非管理员FAIL；取消/通信故障不写成完成的身份比对。
- 日志仍是编号、方式、成败和胁迫标志，没有日期时间或改密/新增等管理操作详情。
- 审计队列满时认证页显示`Audit busy`，不跳过审计直接授予权限。Flash失败保留RAM队列重试；未落盘事件仍会随掉电丢失。

1. 首次新指纹录入及再次识别；验证旧测试手指不能进入，0取消不绕过验证。

4. 退出管理员，主页1验证新数字普通/胁迫口令，主页2验证新旋钮普通/胁迫口令，均PASS，旧口令不匹配；数字*仍每次删一位，旋钮*清空。
5. A重新验证→菜单4，检查NUM/DIAL普通及胁迫记录、FING记录；A/B/#不追加测试数据。
6. 菜单3录第二枚管理员，检查不松手、不同手指、重复指纹各错误路径及0取消。

## 中断恢复

录入前记录待完成ID，待完成ID不授予权限。模板未保存时重试重新走三步。模板已存、名单未提交时，下次首次录入或已授权菜单3显示`PENDING TEMPLATE`，用刚录入的手指按#识别，只有匹配该待完成ID才补全名单。其他旧指纹不能代替完成。

管理员数据全损坏显示`Admin data bad`，不自动擦除或重开首次录入，须检查具体存储故障后恢复。下载更新勿整片擦除，否则MCU名单/口令/日志会丢失，指纹模块中的模板却仍存在。
