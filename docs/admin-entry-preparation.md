> 后续四功能测试已实现，当前以[管理员模块测试](admin-module-test.md)为准。本文作为前期复核记录保留。

核对日期：2026-10-26。此文区分已上板确认、已实现待上板确认和后续设计，避免将驱动可用误认为完整业务已接通。本轮固件只修复主页旋钮认证漏记日志，尚未启用管理员入口。

> 同日需求更新：管理员顶层菜单已由用户明确为“普通密码、胁迫密码、新管理员指纹、日志”四项，指纹录入须逐步按键推进。最新版交互与击键节奏建议见[管理员四功能方案](admin-workflow-spec.md)，优先于本文早期菜单和指纹删除草案。

## 用户已经确认的管理员需求

1. 主页按A进入指纹管理员验证，0取消。
2. 管理菜单提供日志查看、密码修改、指纹新增与删除。
3. 数字与旋钮各自的普通/胁迫口令，四套均可修改；新口令连续输入两遍确认。
4. 本轮经管理菜单新增的指纹全部属于管理员，仅用于管理入口，不作为日常开锁方式。
5. **最后确认的首次部署方案优先**：全部后续功能完成后，额外提供首次管理员录入步骤，让用户现场录入一枚新指纹，作为初始管理员。此前“绑定一个已有ID”的选项已被这条更新取代。
6. 不自动把模块中已有测试指纹认定为管理员，不自动清空既有模板。

## 模块拆分与接入边界

| 后续模块（拟新增） | 职责 | 复用接口 |
| --- | --- | --- |
| fingerprint_service | 初始化与通信检查、搜指纹、录入、查ID占用、删除、错误/取消/进度转换；不决定权限 | AS608_Init/VerifyPassword/ReadLibraryInfo/FindFreeID/JM101Search/JM101Enroll/SetCancelCallback/SetStatusCallback；删除接口另行验证 |
| admin_store | 管理员ID白名单、首次配置状态、角色变更持久化与恢复 | 仿照credential_store双页追加、版本、CRC、最后提交；不复用或清空旧数据区 |
| admin_auth | 成功搜索的ID必须在管理员白名单内，才发出授权结果；会话退出/失效撤权 | fingerprint_service＋admin_store；指纹ID为0也可能合法，必须另设配置标志 |
| credential_editor | 四套口令逐项编辑、二次确认、冲突校验、持久化成功后才切换运行配置 | 数字输入/旋钮输入、Credentials_IsValid、CredentialStore_Save/Load、Auth_Init |
| fingerprint_manager | 管理员内录入/删除、ID列表及存储错误反馈 | fingerprint_service＋admin_store；模板与MCU名单的跨存储一致性处理 |
| admin_app | A入口、指纹等待、管理菜单、返回与会话控制；只调度上述模块 | 独立界面适配，后续挂接全局状态机 |

不把管理员角色直接塞进现有四套口令结构，防止口令修改意外改变管理权限。也不把指纹ID写进输入层的数字密码或旋钮事件中。

管理员中的日志页面复用只读翻阅；当前测试页A写TEST、B批量写130条等诊断操作不开放给正式管理菜单。密码修改成功必须刷新正在使用的Auth配置，不能只改Flash后继续用旧RAM配置，也不能重置尚未落盘的审计事件。

## 首次部署及正常入口流程

首次部署按用户要求放在管理功能完成之后实物进行：确认没有有效管理员配置→由用户明确启动首次录入→读取指纹库和空闲ID→用户按进度放置/移开/再次放置手指→模块最终存储成功→把新ID提交到管理员配置→回读配置并再次用该指纹验证。只有模板和管理员配置都确认成功才提示完成。预置测试模板保留且无管理员权限。

若模块报告该指纹已存在，不自动把旧ID提升为管理员；提示换一枚未录入的手指，或由用户另行明确决定迁移。录入成功而MCU名单保存失败时，提示部分完成并执行明确的恢复流程，不显示管理员已建立。

正常使用：主页A→指纹等待→搜索结果ID白名单检查→管理员菜单→日志查看/四套口令修改/指纹增删→退出撤权。取消、无匹配、通信错误、超时、匹配到非管理员都返回未授权状态。指纹验证不触发舵机开锁。

## 实施前要处理的具体缺口

- **模板与角色分开**：当前驱动只返回匹配ID/分数、模板数量/容量；模板数量不能证明管理员存在，需要新增按ID检查占用能力以及管理员名单恢复检查。
- **删除尚未验收**：保留的Finger_Delete/AS608_DeleteChar存在，但当前主机JM101测试没有覆盖删除，既往硬件确认仅录入/搜索。实施删除前核对该模块文档与返回格式，补模拟测试，再上板验证。
- **Flash空间**：现有程序上限0x0800DC00，日志DC00～E3FF、口令E400～EBFF，其后各旧数据区保留。管理员名单需要独立持久化区；拟从程序区末端划两页，例如D400～DBFF，并将程序上限同步缩到D400。实施时必须重新检查MAP余量、Keil两个链接范围、构建脚本和区域隔离测试。本轮不改地址、不擦写新区域。
- **等待和退出**：指纹一键流程目前是同步等待。取消回调在命令/短等待之间调用；不能在串口收包使用SysTick时调用KEY_Scan/Delay。先用既有回调实现0取消；正式状态机需要可持续处理会话计时与审计服务的调度方式，不能拿返回后的页面切换冒充实时调度。
- **ID双存储提交**：新增指纹需记录模板已存/名单已存两个阶段，并能从取消、通信不确定或掉电中恢复。删除需防止模板操作失败或ID重新使用后误获管理员权限；拟先持久化撤权，再删除模板，保留可重试状态。
- **最后管理员保护（建议规则）**：保留至少一枚管理员，删除须显示目标ID并按#确认；删除当前会话所属管理员后退出会话。正式实现前随管理流程一起确认。
- **会话策略（待定）**：尚未确定管理员会话空闲退出时间、认证失败次数与锁定时长；这些参数不作为本轮准备工作的隐含决定。
- **指纹审计**：log格式已有FING方式，但Auth事件目前只有数字/旋钮来源，audit没有通用入队接口。管理员验证写入需拓展事件入口并保留失败重试/满队列约束。现有日志不区分登录、改密和删指纹等事件，也没有操作者ID；如需完整管理操作追溯，应先明确事件格式及兼容策略。

## 后续实施和实物验收顺序

1. 指纹服务与管理员名单：模拟搜索匹配但非管理员、通信错误、空库、ID0、配置损坏、掉电边界；不预录用户的首枚管理员。
2. A入口和会话，连同日志只读菜单：检查0取消、超时、退出后无授权、测试写入快捷键不泄漏到管理菜单。
3. 四套口令修改：二次不一致/中途取消不保存，普通与胁迫不能相同，写入失败旧口令仍有效，保存后立即生效，重启仍有效。
4. 指纹增删：录入最终成功、重复/满库/取消/通信失败、删除确认、名单与模板一致性及最后管理员保护。
5. 全部模块可用后，提供明确的首次录入流程，由用户现场录入初始管理员；随后逐项在硬件验证A入口、日志、四套改密和增删。此前模拟通过不替代这一步。
