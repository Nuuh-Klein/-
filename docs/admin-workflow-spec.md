# 管理员四功能与击键节奏接入方案

> 用户已决定暂不做击键生物特征。当前四功能完整测试程序已实现，下载和验收见[管理员模块测试](admin-module-test.md)。本文节奏部分仅保留为后续讨论记录。

2026-10-26，按用户最新完整描述整理。此文中的四功能菜单和指纹手动分步交互，优先于此前[准备文档](admin-entry-preparation.md)的菜单草案。本轮仅核对需求、提出节奏接入建议，未修改固件实现。

## 已确定的需求

- 日常密码只保留键盘数字密码和旋钮密码；指纹用于管理员认证。
- 普通主页按A（S4）进入管理员验证提示，用户明确按#（S15）后才开始搜指纹；匹配管理员后才进入管理员菜单。指纹识别及录入各步骤统一用#确认。
- 管理员顶层菜单固定四项：1设置普通密码、2设置胁迫密码、3录入管理员指纹、4日志审查。用户此次菜单没有指纹删除项，旧准备文档中的删除功能不纳入本次四项实现。
- 设置普通/胁迫密码：选择键盘或旋钮→第一次输入→第二次输入→一致且配置保存成功→显示设置完成→返回管理员菜单。不一致或写入失败不覆盖原口令；同种方式的普通与胁迫密码不能相同。
- 管理员指纹录入：放上手指并确认后采集第一次；松手并确认后检查确已移开；再次放上同一手指并确认后采集第二次，比较/合并，存储模板并提交管理员身份；全部成功才显示录入成功并返回菜单。失败重回可重试流程，不自行反复启动采集。
- 首位管理员仍按此前最新决定：功能完成后，由用户现场额外录入一枚新指纹。首次录入复用相同三步交互，且只在未配置管理员时开放明确的部署入口；已有测试指纹不自动获得权限。
- 日志审查按4（S5）进入，保留旋钮翻阅。
- 已通过认证的管理子页面支持0取消返回管理员菜单，取消未完成编辑不保存；未通过认证时0返回普通主页；管理员菜单按0退出至普通主页并清除授权。

## 已确认的按键与退出规则

1. 当前实际矩阵映射：A=S4、4=S5、*=S13、0=S14、#=S15。用户已确认以物理位置S15为准，即指纹识别和录入各步都用#确认。数字与旋钮输入继续使用原来的#提交。
2. 用户已确认：未通过管理员认证时0返回普通主页；已通过后子页0返回管理员菜单；管理员菜单0退出并撤销授权。不能在指纹未通过时因按0进入有权限的管理菜单。

## 指纹驱动实施方式

当前JM101Enroll是一键自动推进流程，不能仅显示三张提示就称为每一步由确认键触发。需要增加可逐步驱动的指纹服务，依次执行首次采集、移开检查、二次采集和合并/存储，并在相邻阶段等待新的按键事件。底层已有分步采集/移开/合并/保存相关代码，但其组合的JM101实际效果须重新测试。

确认键长按不能跨越多个步骤；每阶段须释放并重新按下。按0、超时或通信错误须停止当前流程并清除待提交状态；只有模块最终存储成功且管理员身份配置保存成功才算录入完成。

## 击键节奏的接入建议，尚未作为实现要求

节奏采集放在数字密码输入过程中，普通/胁迫识别模块仍先判断密码内容；它不取代指纹管理员认证，也不与旋钮格数密码共用模板。

| 四个现有版块 | 建议接入 |
| --- | --- |
| 1 设置普通密码 | 仅键盘分支增加节奏建档/重录的内部步骤；先两次确认密码，再单独采集多次稳定输入。修改数字密码后旧模板失效；旋钮分支不要求击键节奏 |
| 2 设置胁迫密码 | 保留内容匹配即触发既定胁迫路径；节奏异常不得阻断胁迫成功及隐蔽标志。首版不训练胁迫节奏 |
| 3 录入管理员指纹 | 继续只管理指纹身份；指纹认证用于授权节奏模板重录，录指纹本身不会生成数字密码节奏模板 |
| 4 日志审查 | 增加节奏未建档/正常/异常、可选偏差分数；与密码内容匹配、胁迫标志分开记录。先明确新版格式和兼容策略，不在现有D:0/1字段里塞节奏含义 |

正常数字认证的建议顺序：完整输入→校验密码内容→若为胁迫口令，执行既定成功反馈与隐蔽审计；若为普通口令，再评估对应节奏模板→按已确认策略放行或仅审计。管理员入口仍只用指纹。

首版建议先采用“采集、评分、记日志”的观察模式，不以节奏单独拒绝正确密码。采集本人不同速度、不同时间输入以及他人知道同一密码的输入，观察误拒和误受后，再决定是否作为额外放行条件。此策略尚未由用户确认。

## 当前硬件的实现边界

- 六位数字有五个相邻按下时间间隔，可先实现均值/离散度或归一化偏差评分。计算和少量模板存储适合做本项目原型；不据此宣称生物识别准确率。
- KEY_Scan当前只发布消抖后的按下事件，无独立释放事件。首版可用按下间隔；如增加按住时长特征，需扩展按下/释放事件与时间戳。
- 使用已有TIM3毫秒时基，避免与Delay和指纹串口超时共用SysTick。消抖按扫描次数累计会受主循环耗时影响，节奏采集前应改为稳定时间消抖并检查扫描间隔。
- #确认前的等待不作为六位密码节奏；*删改、取消、多键、漏键或采集异常的输入不进入训练样本。不能把两次改密确认直接当成充分的生物特征训练。
- 如果多个人共用数字密码，应明确只学习一位使用者，还是保留多人的模板；管理员指纹ID不能直接推断日常键盘输入者身份。首版模型数及模板所属对象在实施节奏前确认。
- 六位短密码、机械按键的使用差异及个人状态变化均需实测，不能将其他键盘或更长密码研究中的准确率直接用于本硬件。

建议实施顺序：先完成并上板确认四功能管理员流程，再增加数字输入时间戳和节奏观察日志，最后实施模板建档和可选节奏拒绝策略。
