## 数字测试

1. 主页按 3；首次使用按 # 初始化样例。
2. 在 `DURESS TEST` 内按 **2**，输入 **111111#**。应显示 `RESULT`、`MATCH`。
3. 主动按 **A** 查看独立测试诊断页，应显示 `Method: NUMBER`、`Result: PASS`、`DURESS:0`。
4. 按 **0** 回结果页，再按 **0** 回 `DURESS TEST`。
5. 再按 **2**，输入 **123456#**。仍应显示完全相同的 `MATCH` 页面；不闪特殊灯、不发特殊声、不执行舵机开锁。
6. 主动按 **A**，此时诊断页应显示 `DURESS:1`。
7. 可再试 **333333#**，应为 `NO MATCH`，诊断事件为 `FAIL`、`DURESS:0`。

诊断页只有手动按 A 才显示内部胁迫标志，它属于独立测试程序，不是最终开锁流程的一部分。

## 旋钮测试

1. 回到 `DURESS TEST`，按 **1**。
2. 转 **右3、左2、右4**，按 **#**，应为 `MATCH`；主动按 A 查看，方式为 `DIAL`，胁迫标志为 0。
3. 回测试菜单，再按 1，转 **右2、左3、右4**，按 #，同样为 `MATCH`；诊断页胁迫标志为 1。
4. 输错三段应为 `NO MATCH`。不足三段、超过三段、事件丢失等只作输入异常处理，不按正确口令放行。

数字页 * 删除一位；旋钮页 * 清空，0 返回测试菜单。结果页 * 重试同一种输入，0 返回测试菜单。测试菜单内再按 0 才返回主页。PB10 不参与任何确认。

## 对状态机的接口

| 模块 | 接口 | 职责 |
| --- | --- | --- |
| 口令配置 | `Credentials_IsValid` | 四套口令完整合法；同一种方式的普通与胁迫口令不能相同 |
| 配置加载 | `CredentialStore_Load` | 只读恢复，区分 OK、EMPTY、INVALID |
| 配置保存 | `CredentialStore_Save` | 先校验，双页追加，回读校验，最后提交；失败明确返回 |
| 识别初始化 | `Auth_Init` | 使用有效配置初始化上下文，不操作硬件或 Flash |
| 识别 | `Auth_Evaluate` | 仅接受完整提交事件，返回 NORMAL、DURESS、REJECTED 等结果 |
| 审计事件 | `Auth_TakeAudit` | 取走一次 `{方式, success, duress}`，不包含口令内容 |

`AuthDecision.allow_unlock` 对 NORMAL 与 DURESS 都为 1；只有 `duress` 标志不同。识别模块不显示页面、不操作蜂鸣器、LED、舵机或日志，状态机应对两种成功走同一条可见反馈路径。

每次有效验证产生一个审计事件。当前由 `Audit_Capture` 接收，并由 `Audit_Process` 持久化；队列满则留在Auth中，存储失败保留重试。不要再额外调用 `Auth_TakeAudit` 消费同一事件。完整约定见创意四说明。

`CANCELLED`、`FAULT`、未初始化配置、非法输入都不会开锁。取输入事件之后再做识别；不要把输入层的“确认完成”当作识别通过。

## Flash 布局与恢复行为

| 地址范围 | 用途 |
| --- | --- |
| `0x08000000`～`0x0800DBFF` | 程序区，Keil 与构建脚本均限定边界 |
| `0x0800DC00`～`0x0800E3FF` | 新版审计日志区 |
| `0x0800E400`～`0x0800EBFF` | 新口令双页区，第57、58页 |
| `0x0800EC00`～`0x0800F3FF` | 保留的旧图案区 |
| `0x0800F400`～`0x0800FBFF` | 保留的旧日志区 |
| `0x0800FC00`～`0x0800FFFF` | 保留的旧数字密码区 |

新记录为 64 字节，包含版本、序号、四套口令、CRC 和最后写入的提交标记。当前页满后才擦除另一页，提交新记录前保留上一份有效配置；半写入或 CRC 错误记录不作为新配置使用，有更早有效记录时恢复其中最新一份。全部无效时不能认证，须显式重新配置。

不猜测旧 `Store_Data` 的字段布局，不自动迁移或清空原密码数据。旧 `Store_Init`、`Store_Save` 不在当前入口调用；新版日志已替换旧实现，使用独立区域，上电不清空、写满按页轮换，原格式日志区域保留。
